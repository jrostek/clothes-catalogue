# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Layout

npm-workspaces monorepo (`apps/*`, `libs/*`) with Nx on top (`@nx/eslint` and `@nx/jest` plugins infer `lint`/`test` targets). TypeScript project references are wired from the root `tsconfig.json`; shared compiler options live in `tsconfig.base.json`.

- `apps/backend` — NestJS 11 API (`@clothes-catalogue/backend`), Swagger UI at `/swagger`, listens on `PORT` (default 3000).
- `apps/backend/tools/aspire-apphost` — Aspire TypeScript AppHost that orchestrates the local dev stack.
- `apps/frontend` — Expo 57 / React Native app (`@clothes-catalogue/frontend`) using expo-router (file-based routes in `src/app/`).
- `libs/dtos` — `@clothes-catalogue/dtos`, request/response types shared between backend and frontend.

## Commands

Install once from the repo root: `npm install`.

### Backend (`apps/backend`)

The unprefixed scripts (`start`, `dev`, `build`, `lint`, `format`) do **not** run Nest — they delegate to the Aspire AppHost. The plain Nest scripts carry a `nest:` prefix.

| Goal | Command (run in `apps/backend`) |
|---|---|
| Full local stack (Postgres + Redis + backend) via Aspire | `npm run dev` (needs the `aspire` CLI; runs `aspire run`) |
| Nest only, watch mode | `npm run nest:start:dev` |
| Build Nest | `npm run nest:build` |
| Lint Nest sources (auto-fixes) | `npm run nest:lint` |
| Lint the AppHost | `npm run lint` |
| Unit tests | `npm test` |
| Single test file | `npx jest path/to/file.spec.ts` or `npx jest -t "test name"` |

Jest config lives inline in `apps/backend/package.json` (`rootDir: src`, `*.spec.ts`, ts-jest). No spec files exist yet, and `test:e2e` points at a `test/jest-e2e.json` that does not exist yet.

### Frontend (`apps/frontend`)

`npm start` (Expo dev server), `npm run web` / `android` / `ios`, `npm run lint` (`expo lint`). From the root: `npm -w @clothes-catalogue/frontend run <script>`.

## Architecture notes

- **Aspire orchestration.** `apphost.mts` provisions a persistent Postgres container (database `clothes-catalogue`, user `asia`, secret parameter `sqlPassword`) and Redis (`cache`), then launches the backend with `addJavaScriptApp('backend', '../..', { runScriptName: 'nest:start' })` — i.e. it runs `npm run nest:start` in `apps/backend`, injecting connection info for `db` and `cache` as env vars. The imported `./.aspire/modules/aspire.mjs` is generated by the Aspire CLI and gitignored; it appears after the first `aspire run`. Aspire hosting package versions are pinned in `aspire.config.json`.
- **Persistence is not wired yet.** Prisma 7 (`@prisma/client`, `@prisma/adapter-pg`, `pg`) is installed in the backend, but there is no Prisma schema and `AppModule` has no database or Redis module.
- **Shared DTOs are type-only.** `libs/dtos` exports raw `.ts` (`"exports": { ".": "./index.ts" }`) with no build step, and DTOs are plain `type`s imported via `import type`. They therefore produce no runtime metadata: Nest validation pipes and `@nestjs/swagger` decorators cannot introspect them. Add new DTOs under `libs/dtos/<feature>/` and re-export them from `libs/dtos/index.ts`.
- **Backend structure.** Controllers live in `src/controllers/`, services in `src/services/`, all registered in the single `AppModule`.
- **Frontend.** Path alias `@/*` → `src/*`. Platform-specific variants use the `.web.tsx` / `.web.ts` suffix next to the native file (e.g. `app-tabs.tsx` vs `app-tabs.web.tsx`). Typed routes and the React Compiler are enabled in `app.json`.
